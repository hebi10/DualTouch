# DualTouch — Android Fold 터치 동기화 실험

DualTouch는 **Galaxy Z Fold의 좌우 분할 화면**에서 사용자가 직접 누른 위치를 반대편 테스트 앱에 재현할 수 있는지 검증하는 Kotlin Android 앱입니다.

> **현재는 POC입니다.** Android 접근성 서비스가 받는 실제 터치는 원래 앱으로 그대로 전달되지 않을 수 있고, 가상 제스처는 진행 중인 입력을 취소합니다. 컴파일 성공은 실제 터치 동기화 성공을 의미하지 않습니다. 금융·결제·비밀번호·타사 일반 앱에는 사용하지 마세요.

## 앱 구성

- `:app` — DualTouch 홈·설정·접근성 고지·분할 가이드·기술 검증과 플로팅 Thumb
- `:probe-left` — Test Left (독립 좌측 탭 카운터 앱)
- `:probe-right` — Test Right (독립 우측 탭 카운터 앱)
- `:probe-common` — 카운터 UI 라이브러리

Android 14 / API 34 이상 실험, Kotlin, Android SDK 35, JDK 17, Gradle 8.11.1, Android Gradle Plugin 8.9.2. 로그인·Firebase·인터넷·결제·광고 없음.

## 화면 구조

| 화면 | 구성 |
|---|---|
| 최초 시작 | 앱 목적·접근성 사용 고지·개인정보 범위 안내 |
| 홈 | 실제 접근성·Thumb 표시 상태, **플로팅 표시 / 숨기기**와 표시 설정 |
| 권한 안내 | 접근성 사용 목적·위험 고지, 사용자가 직접 시스템 설정 이동 |
| 분할 가이드 | Fold 펼침, Test Left·Right 5:5 배치, 실행·방향 설정 |
| 플로팅 Thumb | 소형 원을 탭하면 ① 실행/중지 ② 좌/우 선택 ③ 영점 조절 메뉴 |
| 영점 조절 | 직접 기준점(기본 빨강) 드래그 시 두 점 동행, 자동 기준점(기본 흰색) 드래그 시 흰 점만 이동 |
| 표시 설정 | Thumb 크기·색상·투명도, 터치 기준점 크기·색상(각각)·투명도, 실시간 미리보기, 표시 초기화 |
| 상태·오류 안내 | 유효하지 않은 분할, 접근성 OFF, 긴급 중단·재시도 방법 |
| 고급 입력 방식 | 기존 동시 스트로크 / 순차 탭 / 노드 클릭 POC 모드 |

기본 디자인은 흰색·검은색·중성 회색이며, 다크 모드에서는 차콜 배경을 적용합니다. 정보 구조와 큰 터치 대상(최소 48dp)을 우선하며 그림자·그라데이션·불필요한 애니메이션은 사용하지 않습니다.

## 플로팅 표시 사용 흐름

1. DualTouch를 실행하고 첫 사용 안내를 확인합니다.
2. 홈에서 **플로팅 표시**를 누릅니다. 접근성 서비스가 연결되어 있지 않다면 권한 안내 화면을 표시하고, 사용자가 직접 Android 접근성 설정에서 허용하도록 안내합니다.
3. 권한이 활성화되어 있다면 **두 테스트 앱을 열기 전에도 Thumb를 즉시 표시**합니다. Android 접근성 오버레이(`TYPE_ACCESSIBILITY_OVERLAY`)를 사용하므로 일반 앱 오버레이 권한(`SYSTEM_ALERT_WINDOW`)을 추가 요청하지 않습니다.
4. Test Left와 Test Right를 좌우 분할 화면에 배치하고 Thumb를 탭합니다.
5. 세 버튼에서 **실행·중지**, **좌→우 / 우→좌**, **영점 조절**을 선택합니다. 시작 후 최대 20초 안에 자동 입력을 중단하지만 Thumb는 남습니다.
6. 홈에서 **플로팅 숨기기**를 누르면 Thumb 전체를 제거합니다. 비상 시 기기 볼륨 아래 버튼을 사용합니다.

**기존 화면을 그냥 누르면 자동 복제되는 기능은 Android 기기에서 성공이 검증되지 않았습니다.** Thumb를 띄우는 것은 UI 기능이며, 실행 후 입력을 정확히 전달하는 것은 별개의 기술검증 항목입니다.

## 표시 설정

`설정`에서 다음 값을 바꿀 수 있습니다.

- Thumb 크기: 48~88dp (기본 56dp)
- Thumb 색상: 검정·회색·흰색·빨강·파랑·하늘·주황·노랑
- Thumb 불투명도: 40~100% (기본 90%)
- 직접/자동 터치 기준점 크기: 48~88dp (기본 52dp)
- 직접 터치점 색상: 기본 빨강, 팔레트 8종 중 변경 가능
- 자동 터치점 색상: 기본 흰색, 팔레트 8종 중 변경 가능
- 터치 기준점 불투명도: 40~100% (기본 90%)
- 표시 설정 초기화: 모양만 기본값 복구. 방향별 영점 오프셋은 보존

설정값은 기기 내부 `SharedPreferences`에만 저장됩니다. 실행 중 플로팅 Thumb도 크기·색상·투명도가 갱신되도록 연결했습니다.

## 반응형 화면 대응 — DT-003-R01

기기 이름을 직접 검사하지 않고 Android 앱이 **현재 사용할 수 있는 창 너비·높이(dp)** 에 따라 UI를 전환합니다. 폴드 접힘·펼침, 일반 스마트폰, 태블릿, 분할 창 크기 변경에 대응하기 위함입니다.

| 실제 앱 창 너비 | 배치 | 목적 |
|---|---|---|
| 600dp 미만 | 1열, 좌우 최소 여백 | 일반 휴대폰·폴드 접힘·좁은 분할 창 |
| 600~839dp | 1열, 본문 최대 720dp로 중앙 정렬 | 태블릿 세로·폴드 펼침 일부 화면 |
| 840dp 이상, 높이 480dp 이상 | 홈 및 설정 2열, 최대 폭 1180dp | 태블릿 가로·폴드 넓은 화면 |
| 840dp 이상, 높이 480dp 미만 | 1열·세로 스크롤 | 휴대폰 가로 등 낮은 화면 |

사용 방법과 버튼은 모든 크기에서 같으며 화면 크기만으로 기능을 추가·제거하지 않습니다.

- 홈 넓은 화면은 **서비스 상태·플로팅 제어 / 사용 안내·기술검증** 두 영역으로 나뉩니다.
- 설정 넓은 화면은 **표시 미리보기 / 조절 슬라이더·색상 팔레트** 두 영역으로 나뉩니다.
- 설정의 색상 팔레트와 3개 점 미리보기는 가로로 스크롤할 수 있어 작은 화면에서도 잘리지 않습니다.
- 슬라이더와 색상 터치 영역은 최소 48dp, Thumb와 영점 점도 설정값 최솟값이 48dp입니다.
- 시스템 글꼴 확대 시 버튼 높이를 고정하지 않고 세로로 늘어나며, 플로팅 메뉴는 화면 높이에 맞춰 스크롤할 수 있습니다.
- 시스템 상태바·내비게이션 영역을 고려해 화면/Thumb 메뉴의 안전 여백을 확보합니다.
- 회전·폴드 상태·멀티윈도우 크기 변화로 Activity가 재생성되면 창 크기를 다시 계산합니다. 현재 화면·스크롤 위치를 복원하도록 처리했습니다.
- 다크 모드·큰 글자·스크린리더/실기기 시각 검증은 전체 개발이 끝난 후 최종 Android QA에서 수행합니다.

구현 기준: [공식 Android 창 크기 등급](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes)과 [Views 적응형 디자인](https://developer.android.com/develop/ui/views/layout/responsive-adaptive-design-with-views).

## 개발 및 CI

```bash
gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug :probe-left:assembleDebug :probe-right:assembleDebug
```

GitHub Actions에서 위 명령으로 앱 코드·JVM 단위 테스트 및 3개 디버그 APK를 검증합니다. CI 성공 이후에도 Fold 실기기 입력·접근성 충돌·화면별 수동 QA는 **전체 개발 완료 후** 별도로 진행합니다.

## 배포 정책

코드 PR·Android CI·디버그 APK 생성은 Google Play 자동 업로드가 아닙니다. 코드 배치가 완료되어도 실기기 POC·최종 QA를 통과하기 전에는 실사용 안정성을 선언하거나 서명 AAB/Play 등록·승격을 하지 않습니다. 정식 서명 빌드, 내부 테스트, 비공개 테스트, 정식 출시는 단계별 별도 사용자 승인이 필요합니다.
