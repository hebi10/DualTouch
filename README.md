# DualTouch — 좌우·상하 분할 앱 터치 동기화

스마트폰·폴더블·태블릿의 Android 분할 화면에 **사용자가 직접 연 앱 두 개**를 연결하고, 직접 터치한 좌표를 반대쪽 창에 재현하도록 설계한 네이티브 Kotlin 앱입니다.

> 현재 **기술 검증용 디버그 빌드**입니다. Android 공개 API가 기존 물리 터치를 정상 전달하면서 다른 독립 창에도 입력을 실행하는지는 실제 기기에서 확정 검증이 필요합니다. 모든 앱·게임·동시 터치/드래그를 보장하지 않습니다.

## 사용자 설치

**DualTouch APK 하나만 설치하면 됩니다.** 이전의 `Test Left`·`Test Right` APK는 개발자의 독립 창 계측을 위한 선택용 도구로 남겨두며 일반 사용자는 설치하지 않습니다.

## 사용자 흐름

1. 앱 실행 → 접근성 사용 범위와 위험 고지 확인 → 명시적 동의 체크 → 사용자가 Android 설정에서 DualTouch 접근성 서비스를 직접 켭니다.
2. 홈의 **플로팅 표시**를 누르면 작은 원형 Thumb가 나타납니다.
3. Android 분할 화면에서 **직접 사용할 두 앱을 좌우 또는 상하로 실행**합니다. 동일 앱을 두 번 실행하려면 해당 앱/OS가 독립된 창 2개를 허용해야 합니다. DualTouch는 앱 복제/멀티 인스턴스 실행을 생성하지 않습니다.
4. Thumb 클릭 → 상위 메뉴 3개(실행/중지, 좌/우 선택·앱 연결, 영점 조절) 중 **좌/우 선택·앱 연결**을 누릅니다.
5. 팝업에 실제로 감지한 **좌우(또는 상하) 앱 패키지**를 확인하고, **왼쪽/위쪽 직접→오른쪽/아래쪽 자동 연결** 또는 **오른쪽/아래쪽 직접→왼쪽/위쪽 자동 연결**을 선택합니다. 현재 앱 창 쌍에 대한 명시적 1회 승인입니다.
6. Thumb → **실행**을 누르고 선택한 창을 직접 터치합니다. Android 입력 제약 때문에 입력을 가로챈 뒤 양쪽 창에 가상 제스처를 순차 재생합니다.
7. 입력 오차가 있으면 Thumb → **영점 조절**에서 빨간 직접 기준점과 흰 자동 기준점으로 보정합니다. 빨강 이동 시 두 점 이동, 흰 점 이동 시 흰 점만 움직입니다.
8. **중지**, 기기 **볼륨 아래** 키, 화면 잠금·회전·앱 창 변경, 최대 20초 제한으로 터치 재생을 중단합니다. 다시 사용하려면 사용자가 직접 실행을 선택해야 합니다.

## 안전 설계

- 사용자가 선택한 두 앱의 패키지와 Android 접근성 윈도우 ID로 승인 대상을 고정합니다. **승인은 현재 서비스 세션에만 유효하며, 창 교체·재시작 후 자동 승인되지 않습니다.**
- 정확히 두 앱 창, 같은 디스플레이, 좌우 또는 상하 분할 정렬, 포커스 존재, 보정 좌표 안전 영역과 5:5에 가까운 크기를 확인합니다.
- 시스템 설정·권한 허용·Google Play·금융/결제/인증 앱으로 보이는 패키지, 화면에 비밀번호 또는 포커스된 텍스트 필드가 감지되는 경우를 차단합니다.
- 키보드·큰 시스템 대화상자·다른 접근성 오버레이·예상하지 않은 창이 있으면 중단합니다.
- 가상 제스처 재생 전 매번 조건을 확인하며, 중지 후 이전 세션의 완료 콜백으로 두 번째 클릭이 실행되지 않도록 막습니다.
- 앱 구동 시 기본 OFF, 사용자 실행 지시가 있어야 ON, 20초 입력 제한, 볼륨 아래 긴급 중지, 화면 OFF·회전/폴드·서비스 종료 시 캡처 해제.
- 앱 화면/문자열/좌표 스트림·비밀번호를 서버로 전송하거나 영구 저장하지 않습니다. 표시 설정과 영점·방향만 로컬 보존합니다.
- 민감 화면을 완벽하게 판별할 수 있다는 보장은 없으므로 결제·금융·파일 삭제 등 반복 실행이 위험한 작업에는 사용하지 마세요.

## 앱 구성

- `:app` — **실제 사용자를 위한 단일 앱 APK** (홈·접근성 고지·플로팅 Thumb·분할 앱 연결·실행/중지·방향·영점·표시 설정)
- `:probe-left`, `:probe-right` — 개발/QA용 **선택** 독립 탭 카운터 앱. 일반 사용자 설치에 불필요.
- `:probe-common` — QA용 카운터 UI 공통 라이브러리

## 스마트폰·태블릿 디자인

실제 앱 창 크기 기준 600/840dp 반응형 UI를 사용합니다. 좁은 화면은 한 열, 충분히 넓은 화면은 상태와 설정을 2열로 표시합니다. Thumb/터치점 크기 48~88dp, 색상 8종, 불투명도 40~100%를 로컬에서 변경할 수 있습니다.

## 자동 빌드

```bash
gradle --no-daemon :app:lintDebug :app:testDebugUnitTest :app:assembleDebug :probe-left:assembleDebug :probe-right:assembleDebug
```

GitHub Actions에서 **단일 앱 다운로드 아티팩트 `dualtouch-standalone-debug`**와 별도 **개발 보조 아티팩트 `dualtouch-dev-probes`**를 생성합니다. Google Play 자동 업로드는 하지 않습니다.

## 기술적 한계·최종 QA

Android 14+의 `AccessibilityService.onMotionEvent`는 수신한 터치를 기존 앱으로 통과시키지 않으며, `dispatchGesture`는 진행 중 다른 제스처를 취소할 수 있습니다. 따라서 이번 코드는 **실제 앱을 선택하는 경로와 입력 재생 코드가 연결된 상태**이지만, 특정 제조사/Android 버전·앱에서 제대로 작동한다는 주장은 아닙니다.

최종 QA에서 분할 앱 2개의 터치 30회(각 방향), 원본/복제 중복·누락, 안전 중단, 큰 글자/접근성, Android 앱/윈도우 차단 정확도, Google Play 접근성 API 정책 적합성을 실제로 검증합니다. **실기기 GO/NO-GO 전 PR 병합 및 Play 배포는 보류합니다.**

## DT-017 — 가로/세로 영점 및 중앙 기준선

- 사용자가 연결한 앱 창의 실제 배치가 **좌우(가로)** 인지 **상하(세로)** 인지 창 경계로 구분하여 상대 좌표를 변환합니다. Android의 실제 분할 방향은 시스템에서 바꿔야 하며, DualTouch는 OS 레이아웃을 강제로 회전시키지 않습니다.
- 영점 조절에서 현재 앱 배치가 가로/세로로 표시됩니다. **가로·세로 기준선 방향 변경** 버튼은 정렬 참고선을 세로선/가로선으로 전환합니다.
- **중앙 기준선 위치 슬라이더(20~80%)**와 **50% 초기화**가 제공됩니다. 좌우 두 앱 각각 같은 비율의 얇은 회색선을 표시하며 이 선은 다른 앱의 터치를 받지 않습니다.
- 기준선 조절 시 빨간 직접 터치점과 흰 자동 터치점이 기존 보정 편차를 유지하며 이동합니다. 빨강 드래그 시 둘 다 이동, 흰색 드래그 시 흰색만 이동하는 기존 규칙은 보존합니다.
- 저장 시 **가로/세로 분할과 좌·우(상·하) 방향마다 영점 보정값을 분리**합니다. 기준선 방향·위치도 분할 배치별 로컬 설정으로 보존하고 초기화 시 해당 배치의 기준선만 기본값으로 복원합니다.
- 창이 변경되거나 보정 범위를 벗어나는 경우 저장을 차단하고 자동 입력을 실행하지 않습니다.

**병합은 GitHub 코드 통합만 의미하며 기기 터치 QA 성공이나 Google Play 출시 승인이 아닙니다.** `release/readiness.json`의 실기기·접근성 검증 미완료 상태를 보존합니다.
