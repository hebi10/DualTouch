# DT-REAL-01 — 실제 분할 앱 연결 (단일 APK)
2026-11-19 · 범위: Android 사용자 앱 2개 실사용 연결 경로. 최종 기기 QA 미실행.

## 고객 요구와 구현
- 사용자 설치 APK는 DualTouch 본 앱 1개. 개발 계측용 Test Left/Right 앱 설치 요구 없음.
- 앱 실행/접근성 목적 고지·명시 동의 후 사용자 수동 시스템 권한 활성화.
- 홈 플로팅 표시 → Android 분할창에서 원하는 앱 2개 열기.
- Thumb 3버튼 유지: 실행·중지, 좌/우 선택·앱 연결, 영점 조절.
- 두 번째 버튼의 하위 선택창에 실제 왼쪽/오른쪽 앱 패키지를 보여주고 사용자가 왼쪽 직접/오른쪽 자동 또는 반대 방향을 직접 승인.
- 같은 앱이라도 Android가 독립된 window ID 2개를 주면 선택 가능. 단일 윈도우로 실행 중이면 DualTouch가 임의로 복제·실행하지 않음.
- 안전상 승인한 창 ID/패키지/디스플레이를 세션 동안 고정. 재시작·창 교체·민감 입력·키보드·외부 앱/팝업 시 기본 OFF 및 재연결.
- 실제 수동 탭 좌표를 대상 창 상대 위치에 변환·순차 가상 터치 재생. 화면 녹화·네트워크·개인 콘텐츠 수집 없음.

## 기능 검증 (전체 개발 후 직접 실시)
- 동일 앱 두 창 가능 환경 / 서로 다른 앱 두 창 / 한 앱만 실행 / 세 번째 앱/외부 팝업 시 경로
- 좌우 패키지 확인 후 승인된 창에만 주입, 승인 전 터치 전송 0회
- 왼쪽→오른쪽 30회, 오른쪽→왼쪽 30회 각각 원본/복제 각 1회, 누락/중복/오클릭 집계
- 창 교체·회전·접힘·키보드·텍스트 입력·시스템 대화상자·금융/결제 앱에서 자동 중지
- 20초 자동 중지·볼륨 아래 긴급정지·서비스 비활성화·재시작 후 자동 활성화 금지
- 다크/라이트/폰/폴드/태블릿 Thumb 연결 메뉴의 스크롤/긴 앱 패키지명 가독성
- TalkBack/다른 접근성 서비스와 충돌 시 지원 제한/안내
- Google Play AccessibilityService 인앱 동의/스토어 공개/정책 선언 및 데모 동영상

## 위험과 제품 게이트
1) `onMotionEvent`는 Android 14+에서 물리 입력을 가로채 원래 앱에 전달하지 않을 수 있음. `dispatchGesture`는 다른 제스처를 취소할 수 있음.
2) 두 다른 앱에 각각 실제 1회 재생되는지 **실기기에서 증명하기 전까지** 범용 터치 동기화 지원 확정 금지.
3) 비밀번호·입력 등 감지로 민감 UI를 부분 차단하지만 모든 타사 앱의 보안 상태를 식별할 수 있다고 보장하지 않음. 사용자가 직접 책임을 지는 금융/거래/삭제 작업에는 사용하지 말라는 고지 유지.
4) 앱별 중복 실행 권한/지원 여부는 DualTouch가 통제하지 못함.
5) 실기기 GO 이후 최종 병합·main CI 1회. Play 테스트/정식 출시는 각각 별도 사용자 승인.

## DT-017 상하 분할 + 보정 기준선
사용자가 선택한 두 앱의 배열은 좌우 분할뿐 아니라 상하 분할도 허용합니다. 사용자 앱 연결 메뉴에는 실제 확인된 '왼쪽/오른쪽' 또는 '위쪽/아래쪽'을 표시합니다. 영점 조절에서 가로·세로 기준선 방향을 전환하고 위치를 20~80%로 조절할 수 있습니다. 기준선은 실제 Android 분할 경계가 아니므로 시스템의 분할 방향·비율을 자동 변경하지 않습니다. 좌우/상하 배치와 터치 방향별 영점 오프셋은 별도로 보존하며 해당 배치의 기준선 설정은 초기화할 수 있습니다. 실제 폴드/태블릿 QA는 아직 미실행.

## 화면 검사 및 실행 재개

- 실행과 터치 전송에는 완료된 화면 구조 검사가 필요합니다. 터치 캡처를 해제한 직후 원본 탭과 복제 후보 위치를 확인하고, 원본 탭 완료 후에는 화면이 바뀌었을 수 있으므로 복제 위치와 입력 조건을 다시 확인합니다.
- 정지 상태와 영점 조절에서는 승인된 창 배치와 포커스, 키보드 및 가림 여부를 확인합니다. 실제 터치는 Thumb에서 실행을 눌러 화면 구조 검사까지 통과한 뒤에 보냅니다.
- 키보드나 일시적인 조회 오류로 중지된 경우 같은 창의 승인과 영점을 유지합니다. 차단 사유를 해소한 뒤 Thumb에서 실행을 눌러 다시 검사합니다. 창의 앱, ID, 화면 또는 경계가 바뀌면 새 연결이 필요합니다.

## Fold 실기기 호환성 검증

1. 후보 커밋과 APK 버전, Fold 모델, Android 및 One UI 버전, 분할 방향과 비율을 기록합니다.
2. Test Left와 Test Right를 분할로 열고 중앙 10회와 네 모서리 각 5회를 포함해 방향마다 30회 짧게 탭합니다. 탭마다 두 카운터가 각각 1회 증가하고 의도한 위치가 눌렸는지 기록합니다. 20초 제한에 맞춰 실행을 나누고 누락·중복·오터치·중단·만료를 구분합니다. 좌우 검증 후 상하 또는 비대칭 분할도 확인합니다.
3. 삼성 인터넷과 일반 앱을 열고 단순 페이지, 내용이 많고 갱신되는 페이지, 주소 입력 및 키보드 전환을 각각 확인합니다. 삼성 인터넷에서 정확히 계수할 때는 로컬 카운터가 있는 테스트 페이지를 사용합니다. 화면마다 연결 성공, 원본 탭, 복제 탭, 중지 이유를 따로 기록합니다.
4. 키보드 또는 조회 오류로 중지된 뒤 복제 탭이 추가되지 않는지 확인합니다. 원인이 사라져도 자동 실행되면 실패입니다. 같은 창에서는 다시 고르지 않고 Thumb에서 실행해야 하며, 창 교체·크기 변경·회전·접힘은 새 연결이 필요합니다. 긴급 중지, 화면 잠금, 민감 입력 또는 가려진 위치에는 추가 탭이 없어야 합니다.

실기기 기록에는 화면별 시도 횟수와 원본·복제 성공, 재실행 결과, 중지 문구를 남깁니다. 에뮬레이터 UI 검사와 물리 Fold의 터치 계측 결과를 별도로 기록합니다.
