R11 changes are confined to test/CI code. Use fixed numeric Linux input-event codes (EV_KEY=1, KEY_VOLUMEDOWN=114, EV_SYN/SYN_REPORT=0) and explicit emulator serial, with the synchronization event documented at https://developer.android.com/studio/run/emulator-console . The previous SYN_REPORT alias and strict unnormalized OK check are plausible transport problems, not proven root causes. Record return code and classified response, accept only a zero exit with exact OK or silent output and no unknown/error response, and require one press and one release. Silent transport is not evidence of delivery. Always attempt release after the press; never automatically retry a press. Host transport exceptions no longer kill a running instrumented test. The test retains its stop timeout and failure state.

Use atomic reports in the isolated probe instrumentation, checkpoint each independently state-verified PNG and its SHA-256 and before stop-ready status, collect final report or incomplete checkpoint on host failure, and require the real final completed report for success. Continue to require fresh actual service key receipt and input-off=true markers, actual overlay removal, correct source/scenario and image hashes; a successful transport response alone never passes. If a countdown capture exists, require the countdown to still be active when requesting the stop. Force-stop remains fixture cleanup, not QA success. Added six mocked host transport regression cases (numeric syntax, normalized/empty acknowledgement and rejection, no retry/release on failure, timeout cleanup, release failure, non-emulator rejection) and integrated into Android CI. The exact helper/test Git blob contents were locally verified: 6/6 passed. Actual Android behavior still requires the new CI. No production code, permissions, window inspection limits, key handling, dispatch, readiness or publishing changes.
