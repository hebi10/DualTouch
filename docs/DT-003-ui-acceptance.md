# DT-003 UI 구현·인수 기준

상태: **화면/UI 코드 구현, 자동 빌드·단위 검증 진행**. 폴드 실기기 최종 시각 검수는 사용자의 요청에 따라 전체 개발 완료 후 수행합니다.

## 스타일

- 기본: 라이트 #FFFFFF/#F5F5F5/#191919, 다크 #121212/#202020/#F2F2F2
- 시스템 폰트, 13~26sp 정보 계층
- 상태/문구/실행 버튼 간 구분, 최소 48dp 이상 터치 조작
- 1면 border, 필요 없는 그림자·둥근 모서리·그라데이션·애니메이션 추가하지 않음
- 슬라이더 및 색상 선택은 설정 페이지에서 바로 조절 및 로컬 반영

## 화면 체크리스트

|---|---|---|---|

| SCR-02 | 접근성 | 서비스 작동 범위·위험·데이터 안내, Android 설정 이동 | 시스템 설정으로 이동, 사용자가 직접 허용 |

| SCR-09 | 고급 실험 | 동시·순차·노드 클릭 | 위험 설명과 별도 명시적 시작 |

## 설정 기능 인수 기준

- 48~88dp의 Thumb/마커 크기 조절, 터치 제한보다 작은 크기 비허용
- 불투명도 40~100% 조절(완전히 투명하게 할 수 없음)
- 8종 색상 팔레트, 직접 기본 빨강·자동 기본 흰색
- 설정 변경 시 즉시 저장, 실시간 미리보기만 갱신하여 사용 중 슬라이더 조작이 끊기지 않음
- 접근성 서비스가 실행 중이면 Thumb 및 영점 마커 색상·크기·알파 실시간 갱신
- 표시 초기화는 영점 보정·방향 선택을 지우지 않음
- 홈의 플로팅 표시는 서비스 연결 후 별도 두 앱 창이 없더라도 컨트롤이 나타남
- 홈의 플로팅 숨기기는 모든 오버레이를 제거하고 입력 캡처 OFF
- 서비스 OFF인 경우 접근성 안내로 이동, 자동 권한 승인 없음
- 현재 POC는 자체 테스트 앱에만 클릭을 전달, 타사 앱은 지원 범위 제외
- 실행 상태, 앱 종료, 20초 타이머, 권한 종료, 접힘·창 변경 시 원본 입력 잠김이 없어야 함(실기기 검증 필수)

## 자동 검증과 미검증 구분

자동: AppearanceRules 크기·투명도 한계·대비색·기본 색상 단위 테스트, 기존 창/좌표/영점 관련 단위 테스트, Android 빌드·디버그 APK 3개 생성.

전체 완료 후 실기기: Fold 세로 펼침·접힘, 스플릿·오버레이 포커스, 라이트·다크·큰 글자, 진짜 화면 캡처, 눌림·드래그 가림, TalkBack/접근성 충돌, 두 테스트 앱 카운터의 좌/우 각 30회 정확성, 20초·볼륨 키 중지.
